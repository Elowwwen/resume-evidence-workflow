# Application-Ready Resume

A rewrite is complete only when the user has a final artifact suitable for the intended application channel.

## Workflow checks

- The selected resume skill received the job description (JD), matching matrix, relevant evidence, required retained content, and the user's explicit presentation instructions.
- The final resume follows the user's latest instructions and covers the intended job-description (JD) priorities.
- The workflow did not proactively add information that the user neither supplied nor requested.
- Any presentation choice that differs from the evidence record remains separate from that record.
- The resume does not expose internal labels, confidence scores, placeholders, or advisor notes.

## Market and language checks

- Conventions fit the target country, language, industry, seniority, and company type.
- English resumes are written as native recruiting documents rather than literal Chinese translations, and vice versa.
- Sensitive personal information and photo conventions match the target market and user preference.

## Selection and user control

- Material deletions or mergers were approved.
- The selected resume skill and any overridden rule are documented internally.
- Confirmed preferences for summary and target position were reused; unresolved choices were clarified.
- The intended-position decision accounts for whether the file is dedicated to one job description (JD) or may be reused for multiple roles. Do not insert a narrow target role by default when broader reuse matters.
- The user's section choices override defaults in the selected resume skill or template.
- Formal employment, internships, and non-employment entries remain clearly distinguishable; formal work experience is not placed inside or overshadowed by an internship-led structure.
- Section selection and ordering fit the candidate's career stage as well as the target job description (JD).
- Section names fit the target job description (JD) without misrepresenting employment type, role, or ownership.

## Content review

- Preserve V0 and run `grooming.md` after targeted revisions.
- Show material changes with their corresponding JD requirements and evidence.
- Chinese writing may use concise context and meaningful work-focus labels; English uses action-led standalone bullets with necessary context integrated. Write natively for each language.
- Plan space before drafting and inspect the first content render before final review.

## Artifact checks

- Deliver the format the application requires.
- If HTML is selected, read `editable-html-output.md`, build from `../assets/editable-resume-base.html`, and verify the editing toolbar instead of delivering static HTML.
- Preserve the source layout when requested.
- Check page count, clipping, overlap, whitespace, font readability, alignment, links, and print/export behavior.
- Ensure the file opens independently and does not rely on missing local assets.
- Name the artifact clearly for the company and role when appropriate.

## Final handoff

Provide the finished resume, not only a critique or diff. Briefly state:

- which resume skill or fallback method was used and why;
- the most important positioning choices;
- unresolved evidence gaps that could matter in interview;
- how to make future variants from the saved evidence bank.

## Public examples and case libraries

If creating a README, example, case library, test fixture, screenshot, or public demonstration, use wholly fictional identity and career data. Change names, organizations, dates, project details, and metrics together. Never repurpose a user's private evidence merely by removing their name.

# Resume Evidence Workflow

一套面向各类 Agent 和对话式 AI 的完整简历工作流，覆盖职业经历盘点、岗位描述（JD）匹配、简历改写和投递版本生成。

它先帮助用户发现容易被忽略的经历与价值，建立可复用的 Markdown 经历证据库；获得目标岗位描述（JD）后，再解读岗位要求、匹配证据，根据岗位需要进行定向改写；需要具体写作方法或文件生成能力时，再调用其他 Skill。

## 主要特点

- 在没有岗位描述（JD）时也可以先盘点经历，不把所有深挖推迟到投递阶段。
- 用自然、具体的问题帮助用户回忆，内部保留专业判断。
- 区分事实、估计、解释和简历呈现选择，不凭空补充经历。
- 先制作岗位描述（JD）—证据匹配矩阵，再决定简历的强调、压缩或改写方向。
- 由本工作流统一执行，按需借用其他 Skill 的具体方法或文件生成能力。
- 在改写阶段发现的新事实、更新数据和项目进展会同步回经历库，并向用户说明。
- 首次解析简历后可保存 `基础简历.md` 与 `简历版式档案.md`；以后处理新的岗位描述（JD）时不必反复上传同一份 PDF。
- 深挖时会适度询问协作、困难、决策、复盘等行为面试常见内容，保留下来的经历也可以辅助后续面试准备。

## 怎么使用

### 方法一：把仓库链接交给 Agent

复制本仓库链接，直接告诉 Agent：

```text
请读取并使用这个仓库里的简历工作流：<仓库链接>
```

如果 Agent 支持从 GitHub 安装 Skill，也可以让它克隆或安装整个仓库：

```bash
git clone <仓库链接>
```

安装时保留仓库原有目录结构即可。

### 方法二：上传给对话式 AI

下载仓库后，向对话式 AI 上传：

- `SKILL.md`
- `references` 文件夹中的全部 Markdown 文件
- 如果需要生成可编辑 HTML，再上传 `assets/editable-resume-base.html`

然后告诉它：

```text
请完整阅读 SKILL.md 和 references 中的文件，并按照这套工作流帮助我盘点经历、匹配岗位描述（JD）和改写简历。
```

`agents/openai.yaml` 主要用于支持 Skill 配置的 Agent；普通对话式 AI 不需要上传。`README.md` 和 `LICENSE` 也不是运行工作流所必需的。

完成首次经历整理和简历导入后，可以把 AI 生成的 `经历库.md`、`基础简历.md` 和 `简历版式档案.md` 一起保存。下次换一个对话或 Agent 时上传这三个 Markdown 文件即可，通常不需要重新上传原始 PDF。

### 反复使用：可选的方向母版与项目素材库

初次建立基础简历时，工作流会询问你主要投哪些职位或方向；已经说明过就直接复用。若你反复申请不同方向，可以选择建立几份方向母版，例如品牌营销、社区运营或用户研究。只有一个方向时，一份就够，数量由你的目标决定。

方向母版保存该方向常用的经历选择、顺序与表达，减少每次从头整理的工作，保持叙事连贯。每个具体 JD 仍会重新分析、选取证据并复核改写，母版只是起点。公司专用删改不会自动变成长期默认。

项目素材库则保存已确认项目的背景、职责、过程、成果及可用能力角度，适用于研究、运营、创作和技术等项目。它帮助你找到被旧简历遗漏的素材，按 JD 选择和展开。事实仍以经历库为准，避免多份资料各说各话。

### 看见每次改写的依据

改写后会进行 Grooming：重新阅读完整 JD、查阅相关证据，并比较原稿与新版。你会看到关键表达的前后变化、对应的 JD 要求和使用的证据，以及仍缺少素材的部分。

默认分析哪些经历可以适配、哪些要求存在证据空白。只有你问“适不适合”“该不该投”等问题时，才给整体判断与投递建议。

### 网申时分别复制字段

生成可编辑 HTML 后，点击工具栏的 **“网申正文复制”**。每段经历显示四个独立文本框：完整公司名、职位名、日期、工作内容。各框有自己的复制按钮，可分别粘贴到网申对应字段。

- 复制内容包含该段经历的概述与全部正文要点，保留换行。
- 公司名、职位名与日期分别复制；工作内容框包含概述与正文要点，不混入这些字段或地点、部门。
- 面板读取当前简历内容，编辑正文后会同步更新；中英文按各自页面分别列出。
- 浏览器不允许自动复制时，文本会自动选中，按 `Cmd+C`（Mac）或 `Ctrl+C`（Windows）即可。
- 复制面板不会出现在打印或导出的 PDF 中。此功能方便手动填表，不保证招聘网站能自动解析简历。

已有 HTML 不会因更新 Skill 自动获得按钮。可让 Agent 将新版模板的正文复制控件移植到原文件，保留原文、版式和编辑功能。

### 从 HTML 导出 PDF

点击简历里的“生成 PDF”后，请在浏览器打印设置中关闭页眉和页脚：Chrome / Edge 展开“更多设置”并取消“页眉和页脚”；Safari 点击“显示详细信息”并取消“打印页眉和页脚”。否则 PDF 可能包含日期、网页标题、本地 HTML 路径或页码。选择 A4，并在保存前确认预览只有一页。

## 使用示例

```text
请使用这套工作流，先帮我把现有简历里的经历逐段盘点清楚，建立 Markdown 经历库。现在还没有确定岗位描述（JD）。
```

```text
请使用这套工作流，根据这份岗位描述（JD）检查我的经历库，先给出岗位描述（JD）—证据匹配矩阵，展示改写依据并完成定向简历。
```

语音输入或转写文本也可以直接作为经历叙述。识别不清的姓名、日期、数字和专有名词应先确认，不能把转写猜测直接当成事实。

## 输出与注意事项

- 经历库默认保存为 Markdown；HTML、Word 或其他格式按用户需要另行生成。
- 删除经历或要点前必须取得用户同意。
- 最终格式按用户需要确定，必要时使用文件生成 Skill。
- README、示例和测试材料不得使用真实用户的个人信息或可识别经历组合。

```text
├── SKILL.md

├── references/

│   ├── project-material-library.md
│   ├── grooming.md
│   ├── editable-html-output.md
│   └── 其他按需读取的工作流文档
└── tests/copy-description.test.cjs
```

具体工作流、证据结构、提问停止规则、语音输入处理和简历 Skill 路由规则均在 `SKILL.md` 及其按需引用的文档中。
